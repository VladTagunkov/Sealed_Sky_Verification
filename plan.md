# Trusted Edge AI Oracle - Hackathon Plan

## 1) Project Goal

Build a verifiable oracle pipeline where edge AI inference is signed by trusted hardware (USB Armory) and accepted on-chain only when cryptographic proof is valid.

## 2) One-Sentence Pitch

"TEE-backed hardware oracle proving that AI inference happened on trusted physical hardware."

## 3) MVP Scope (Must-Have)

- Edge input is produced from a local source (camera/sensor or test payload).
- USB Armory signs inference context via `SignInference`.
- Backend verifies proof before sending transaction.
- Smart contract records accepted inference + payload hash.
- Frontend demonstrates full flow: generate proof -> submit -> show tx hash.

## 4) Architecture (MVP)

- **Edge layer (Pi/simulated input)**: creates `timestamp`, `imageHash`, `result`.
- **Trusted signer (USB Armory)**: signs `pothole_detected|timestamp|imageHash` internally.
- **Backend**:
  - `/sign-inference` sends `timestamp|imageHash` to USB.
  - `/submit` verifies proof and submits `payloadHash` on-chain.
- **Smart contract**: stores inference submission and emits event.
- **Frontend**:
  - `input.html`: hash/proof generation.
  - `index.html`: verified submit and transaction feedback.

## 5) Verification Model

The contract/back-end verification proves:

- **Integrity**: proof matches exact payload fields.
- **Provenance**: proof is generated by trusted device secret/key.
- **Freshness/replay control**: timestamp and future nonce checks (next step).
- **Auditability**: immutable event log and tx history on-chain.

It does **not** prove semantic truth of the scene (e.g., actual pothole), only trusted origin and integrity of the claim.

## 7) Demo Script (2-3 minutes)

1. Generate a test inference (`sending_information_to_the_ground`).
2. Click generate proof (`input.html`).
3. Submit from `index.html`.
4. Show backend verification success.
5. Show on-chain transaction hash and emitted event.
6. Explain trust boundary: edge hardware signs, contract enforces.

## 8) Roles (Small Team Template)

- **Hardware/TEE**: USB Armory applet, signing, attestation path.
- **Backend/Web3**: verification logic, contract integration, RPC reliability.
- **Frontend/Product**: operator flow, dashboard, demo UX.
- **Pitch/Docs**: threat model, architecture slide, judge-facing narrative.

## 9) Risks and Mitigations

- **USB/network instability** -> use reconnect script + retry strategy.
- **Proof mismatch bugs** -> keep one canonical payload format doc.
- **Demo-time chain latency** -> pre-fund wallet, use fast RPC, show pending state.
- **Scope creep** -> lock MVP early; stretch goals only after green demo.

## 10) Definition of Done

- One-click operator flow from proof generation to tx hash display.
- Proof verification is deterministic and reproducible.
- Contract emits verifiable submission events.
- Team can explain exactly what is verified and what is not.
- Demo can be repeated 3 times in a row without manual debugging.
